## 批次43：正文 md 原生渲染＋去掉无效提示＋自动保存

作者原话（三条）：

> 「现在正文区域没有适配 md 格式原生渲染么，还有，你加了很多无效的提示，然后文件添加了，修改了，也没发保存」

### 43-① 正文 md 原生渲染

- 渲染基座换成老线同款：`marked` 解析 ＋ `DOMPurify` 清洗（两者本来就在 `package.json`，属复用不是新增依赖）。
- 落点：正文面（章节）、条目面、资料面、剧本面、提案面——凡是「读一篇文」的地方都走同一条 `renderMarkdown` 路径。
- 安全口径：`marked@18` 故意宽松（不剥 `<script>`、不管 `javascript:`），所以有 DOM 的地方一律 DOMPurify ＋ allow-list；
  主进程那条零 DOM 的路走 `src/utils/sanitize.js` 的同源表。两条路的危险面同样封死。
- 写作面（编辑态）保持 textarea——那才是稿子；渲染只管读态。

### 43-② 去掉无效提示

- 常驻 notice（已载入 N 字／第 N 版之类）从正文面清掉：那是对开发者说的，不是对作者说的。
- 头部只留一行 `.doc-title`；元信息（路径／版本／字数）沉到正文之下的 `.doc-meta-hint`。
- 保存反馈只留一枚 chip：保存中…／已保存／保存失败（失败才附「重试／重新载入」动作）。

### 43-③ 自动保存落盘

作者说「文件添加了，修改了，也没发保存」——根因不是保存坏了，是保存只在 Ctrl+S 那一按，
作者没有义务记得按。

- `AUTOSAVE_DELAY_MS = 1500`：停手 1.5 秒后自动落盘，每种目标各有一只计时器（正文／大纲／条目／约束／资料／剧本各一只，不互相踩）。
- 自动保存与 Ctrl+S 走**同一条路**：同一个 `expectedRevision`、同一套 chip、同一套冲突拒绝——所以它不绕修订号闸，也不静默覆盖别人的改动。
- 只读到前段（truncated）的文档**不自动落盘**：存下去会把没载入的后半段抹掉，那种情况仍旧要作者自己按 Ctrl+S（界面会说明）。
- 指纹基线：内容没变就不写盘（不制造无意义的第 N 版）。
- 大纲改名同步树：改了大纲节点标题，索引窗那一行跟着换名（不再一个改一个不改）。

## 批次44：蓝色标签、世界书排布、形态三分类

作者原话：

> 「你在前端设计了一些蓝色的标签，看上去能跳转，但是其实不行，非常矛盾，而世界书里面，
> 图表列的切换全都挤在左侧小区域里进行，右侧大面积留空，非常别扭，更合理的一个情况是，
> 上面放图表列，下面放详情信息，这样显然更合理。总而言之，我希望你在一开始就想明白，
> 每个类型的组件到底是用文档还是用 HTML 去实现。原则上来讲，我们鼓励每一种跳转和悬浮的显示，
> 都可以通过一些小窗、弹窗，以及系统内嵌的一些浏览器去实现举个例子，后续假如我们真的要把
> ComfyUI 挪进来，那一定是要通过浏览器去把这个端口承载起来而不可能说我们自己手搓一个组件，
> 对吧所以说，包括世界书，你不要纠结于每一个东西都用文档去做，可以把一些东西放宽，
> 用不一样的结构、不一样的载体去实现」

### 44-A 蓝色标签：看着能点就必须点得动

**病根**（不是配色问题，是两份规则对不上）：

- 渲染侧用一份词表把条目名包成 `.nx-wikilink`（蓝＋虚线下划线）；
- 点击侧用另一份匹配规则找归属条目。两份对不上，就出现「染了蓝却点不动」。

而且旧词表有两处漏洞：列表项给的是 `aliases`（别名），阅读态给的是 `keys`（关键词）——旧代码只读 `keys`，
在列表语境下拿到的是 `undefined`；短名（「人物·柯秒」的「柯秒」）与标签词更是根本不在旧匹配规则里，
于是一条也解析不出来，却照样染了蓝。

**修法**（`next/shell/wikiLinks.mjs`）：

| 函数 | 作用 |
|---|---|
| `entryLinkTokensOf(entry)` | 一条条目贡献的全部候选词：全名、短名（`·` 后缀）、aliases／keys／tags；长度 <2 与重复的不算 |
| `buildEntryTokenMap(entries)` | **只收「恰好指向一条条目」的词**：一个词若落在两条以上条目上（通用标签「记忆」「结构」就是这种），它根本不入表——正文里就当普通文字，不染蓝 |
| `ownEntryTokens(entry)` | 当前条目自己的词不链（链到自己等于没跳） |
| `linkifyEntryNames(root, names)` | DOM 后处理（不碰 HTML 字符串——正则改 HTML 是转义漏洞的温床） |

**一条纪律贯穿**：渲染与点击**共用同一张表**（`buildEntryTokenMap`），所以链进去的词点下去一定打得开；
染了蓝还点不动，比不染更坏。

**顺带修掉一个更隐蔽的种子**：两条正文恰好一模一样时 `v-html` 不会重渲染（innerHTML 相同＝不 patch），
上一条留下的蓝链就留在原地——那条蓝链是按**上一条**的归属算出来的。渲染容器现在带
`:key="entry.path || entry.name"`，换条目时整块重来。

### 44-B 世界书：上＝图表列，下＝详情信息

作者说的别扭是几何问题：视图切换（列表／表格／图谱）挤在两百多像素宽的窄栏里，右侧大片留空，两头都不好用。

**改后的布局**：

```
核心区（竖排）                      窄栏（200–360px）
┌────────────────────────┐         ┌──────────────┐
│ 图表列（看板区）         │         │ 类别导航树    │
│ 列表／表格／图谱＋筛选    │  ← 共用 │ 全部／人物／  │
├────────────────────────┤  一格   │ 编年／设定    │
│ 详情信息（选中条目）      │         │              │
└────────────────────────┘         └──────────────┘
```

- 核心区新形态 `entries-workspace`（看板面）：上＝`EntriesBoard`（三态视图＋筛选＋排序），下＝`EntryDetailPanel`（选中条目）。
- 窄栏退成 `entries-categories`（类别导航树）：只管「按类别找条目」，点一下＝给核心区加一道筛选。
- 两边共用 `data.entriesFilterCat` 一格状态——不各记一份。
- 视图记忆（列表／表格／图谱）按项目根落 `localStorage`（键 `entriesView.<projectRoot>`），换项目各记各的。
- 窄栏保留了「＋ 新建条目」（IDE 的「新建」本来就是文件树的动作）；建完条目在看板区显形。

### 44-C 形态三分类：一开始就想明白每种东西用什么做

新增 `next/shell/formTaxonomy.mjs`，三档形态，渲染器一律归宿主：

| 形态 | 是什么 | 视图类型 | 载体例子 |
|---|---|---|---|
| **文档面 document** | md 文档为主：宿主渲染阅读态（md → HTML）与编辑态（textarea） | `reader`／`editor` | 正文、条目、大纲、构思、约束 |
| **看板面 board** | 结构化数据（清单／表格／图谱）：宿主渲染视图，数据来自载体的 JSON 清单 | `board`／`tree`／`list`／`graph`／`diff` | 世界书工作区、记录型载体 |
| **应用面 app** | 外部网页应用（ComfyUI 那种自带端口的服务）：宿主只给一块内嵌浏览器，界面自己长 | `app`／`custom` | 将来的 ComfyUI 承载位 |

**跳转与悬浮的三条去处**（同一份口径，界面层照它选形态）：

1. **小窗**：overlay 槽的浮窗（宿主渲染与定位，载体只声明意图）；
2. **弹窗**：上下文菜单／设置二级页（宿主 chrome）；
3. **内嵌浏览器**：应用面（外部端口上的服务，宿主给 iframe）。

三条都是宿主的地盘——**载体不自己开窗、不自己弹层**。

**应用面（`external-app`）这一批落地的东西**：

- 宿主视图类型从六个加到八个：新增 `pinax.view.board`（看板面）与 `pinax.view.app`（应用面）。
- `next/shell/ExternalAppHost.vue`：一块 iframe，地址摆出来给作者看（能一眼看见自己开的是哪个端口，也能复制出去单开）；
  iframe 加载失败时给一句人话（「先确认那个端口的服务起没起」），不给作者一个白框。
- 清单校验 `validateAppPane`：地址必填、只认 http/https、**只认本机回环**（127.0.0.1／localhost／::1）、上限 300 字；
  `view` 与 `kind` 必须成对（写一半，宿主就不知道该挂 iframe 还是给宿主视图）。
- 内容安全策略放开 `frame-src 'self' pinax-plugin: http://127.0.0.1:* http://localhost:*`——只放开回环端口，外网地址塞进去只会白屏。

**边界**：这一批只把「承载位」与合同做出来，**还没有真的接 ComfyUI**（那要另起一批：起服务、声明 app.url、把它摆进载体）。
清单校验里「只接回环」这条是有意为之——内嵌浏览器能把本机文件面整个敞给页面，远端地址本批不接。
