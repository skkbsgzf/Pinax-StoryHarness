# 批次68-R6 工单：正文实时编辑渲染＋右栏停靠结构化（浮层越界治理）（2026-11-07）

> 调度方：Zcode。执行方：Qoder CLI（Qwen3.8-Flash）。
> 触发：作者 2026-11-07 裁定——①正文「默认居然不能编辑，应该是默认实时编辑渲染的」；②截图红框两处（快捷词钮、分页条）与 Agent 面板重合，「全局有很多 UI 重合的地方，想想怎么做」。

## 调度方诊断

1. **重合是结构性的**：Pi-Agent 坞（RuntimeDock）以浮层方式占右缘，中心列内容延伸到它底下——正文右缘的一切控件（快捷词钮、chapter-pager、保存 chip）都会被压在 Agent 面板底下。这不是某个控件的 bug，是**停靠模型**问题：浮层必须声明「允许覆盖谁」，正文类内容永远不允许出现在 Agent 底下。
2. **编辑模型**：正文当前「阅读态默认＋头部编辑钮切换」（CarrierPaneHost.vue:128 口径）。作者要的是**点入即改、即时渲染**——阅读即编辑入口，不需要先按编辑钮。

## 任务（两条）

### 任务一：右栏停靠结构化（先做，全局收益）

1. **Agent 坞占位化**：RuntimeDock 从浮层改为布局占位（flex 兄弟或中心区 `padding-right` 绑定坞宽）——正文、页签行、窗体一切右缘控件**永不**进入 Agent 面板底下。坞收起/宽度变化时占位同步。
2. **浮层清单审计**：grep 全壳 `position: fixed|absolute`，逐个登记「归属＋允许覆盖谁」落 §7 表（悬浮球、CollapseOrb 面板、PaneFormMenu、composer typeahead、写作工具弹层、吸附预览、保存 chip…）。规则：**弹层类**（点开才现、明确短命）允许压内容；**常驻/半常驻类**（工具钮、分页条、保存 chip、页签行）必须落在自己的面板边界内。
3. **真窗判据**：对半分屏＋Agent 开启时，正文右缘三样（快捷词钮、分页条、保存 chip）的 `getBoundingClientRect()` 与 Agent 面板矩形**零相交**。

### 任务二：正文默认实时编辑渲染

1. **点入即改**：正文阅读态点击正文任意处＝就地进入编辑（该文档的 textarea 在原滚动位置接管），无需先按「编辑」钮；失焦或 Ctrl+S 保存回渲染态。头部「编辑」钮退役（保存 chip 与取消路径保留）。
2. **渲染管线不变**：仍是「textarea 源文 ⇄ mdRender 渲染」单一管线（批次26 口径），**不做 md 双向转换的第二套**；实时感由块级实现达成——执行方二选一：
   - **块级 live-render**（preferred）：正在编辑的段落显 textarea、其余段落保持渲染（Obsidian live preview 式），失焦即渲染；
   - 或整篇 textarea 接管＋失焦渲染（实现最简，实时感弱一档——选这条须在 §7 说明理由）。
   `@tiptap` 已在 deps（B5 挂账）——若选它做块级编辑器，视为「使用既有依赖」不属新增，但 md 往返保真须有测试钉住（小说是纯散文，md 元素极少，往返丢失＝high）。
3. **分页兼容**：`text-pages` 分页阅读与实时编辑共存——进入编辑时自动整章展开（分页条隐藏），保存回分页；快捷词/取名插入落点（既有「先切编辑态再落字」）改走新入口。
4. **范围**：本批只做**正文**（novel.editor）；构思/大纲/约束/剧本/资料的「阅读态＋编辑钮」是否跟进同模型，登记不下（等作者看过正文效果）。

## 禁止边界

mdRender 管线与 wikiLinkRanges 不动；写族闸/提案轨/自动保存（AUTOSAVE_DELAY_MS）语义不动；workspace 状态轴、composer 三层、世界书三栏（68-R2/R3 成果）不动；不加新依赖（tiptap 既有除外）；不自设阈值当闸；visual-contract 零放宽（新判据随登记）。

## 新增机器判据（visual-contract）

- ⑳ 停靠占位：中心列布局声明中必须存在 Agent 坞占位（padding-right 或 flex 占位）与其宽度的绑定链；正文右缘控件声明不得出现越出主面板的定位。
- ㉑ 实时编辑：novel.editor 模板不得再保留「编辑」入口钮（保存 chip/取消除外）；阅读态正文容器必须带「点入进编辑」的交互声明。

## 验收判据
