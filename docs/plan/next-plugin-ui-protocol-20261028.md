# Pinax 载体 UI 设计协议 v1（2026-10-28）

> 作者裁定：每个模块（载体/插件）都需要有自己的设计协议——任何题材（TXT、MD、HTML…）都能丝滑放进框架，
> 不管单独放还是并排放都保持兼容，不出现「按钮飘在天上」的感觉。**借鉴 Obsidian**：
> 插件渲染进宿主给定的容器、用宿主的 CSS 词汇、不自带窗口 chrome；设置项登记进统一设置页；
> 命令登记进命令面。本协议把这些落到 Pinax 的合同上，并配机器门禁。
> 执行批次：20（本档 §4 的三项改造）。

## 0. 三条归纳（作者之问的直接回答）

**顶部栏有用/没用归纳（现状 → 精简后）**

| 现菜单组 | 判定 | 理由与去向 |
|---|---|---|
| 文件 | **有用，改名「项目」** | 新建/打开/导入/备份/历史/退出全是项目级动作；「最近项目」未实现 → 删（记账） |
| 编辑 | **有用，保留**（最多加的一个） | 撤销/剪切/粘贴是系统级标配；给 id 走主进程 webContents 分发，页内菜单行可用 |
| 视图 | **没用，删组** | 「焦点×3」键盘少数派（记账）；缩放已进偏好节（native zoom 与 zoomFactor 双轨冲突）；DevTools/重载 → 帮助组 |
| 运行时 | **没用，删组** | 「提问」右栏输入框就是入口；「工具面」右栏折叠已有；「打开提案目录」→ 并入项目组 |
| 窗口 | **没用，删组** | 最小化/关闭 = 系统窗控（overlay 已有）；缩放 = 视图，已删 |
| 设置 | **有用，保留** | 主题/偏好与模型/载体管理 |
| 帮助 | **有用，保留** | 规范/门禁；DevTools/重载从视图迁来 |

精简后四组：**项目 / 编辑 / 设置 / 帮助**。

**设置弹窗归类（Obsidian 式）**：顶部搜索框过滤目录；左栏分组——**「应用」**（偏好与模型/备份与恢复）与**「项目」**（载体管理/导入既有稿/新建项目/主载体选择/文档历史）之外，**每个载体可经 manifest 声明自己的设置节**（自动收录进「载体」组）——这是"插件设置进统一目录"的注册制。

**设计协议的必要性**：现在四个视图（正文/条目/构思/资料）各自长出来的头部、按钮、提示语已经出现分叉（「保存为第 2 版」vs「保存」、「已载入 N 字」蓝条 vs meta 行、占位文案泄漏事故）——没有协议，每加一个载体就分叉一次。

## 1. 基础 UI 规范（pane 呈现在中间区域时）

**P1 容器与 chrome**：载体面板渲染进宿主给定的中栏容器；**不自带标题栏/边框/关闭钮/背景色**（背景 = 宿主 `--surface-workbench`，滚动 = 宿主容器）。插件的 SFC 里不许出现 fixed/absolute 全屏元素（弹窗走统一二级页）。

**P2 pane 头部（统一结构）**：每个视图以 `.nx-pane-header` 开头——左：`h4.pane-sub` 标题（载体提供文案）；其下 `.editor-meta`/`.entry-meta` 一行元信息（文件 · 修订 · 字数）；右：动作位**最多 2 枚** `.control-*`（主操作）。元信息与动作位之间不放提示条。

**P3 反馈纪律**：保存反馈 = 自动消失 chip（H1 引入的 `save-chip` 词汇，成功 2.5s 淡出、失败常驻＋重试）；**版本号不进按钮文案**（「保存」，不是「保存为第 2 版」——版本在历史面板看）；**不用蓝色 notice 条承载瞬时状态**（那是旧形态，已废）。

**P4 空态**：每个视图必须有 `.pane-hint` 空态行——一句话说清「从哪里开始」（如「从左边索引窗里选一章」），有建第一篇的动作就带上。禁止空 pane 白板。

**P5 收起与折叠**：索引窗树 v1 常展开（不做折叠）；面板内部区块折叠用 `<details>`（老版词汇）；折叠状态不持久化（记账）。索引窗整体开合 = 竖条同格再点（Obsidian 行为，已实现）。

**P6 占位纪律**：未实现的视图显示占位说明**只在 `viewKind === 'placeholder'` 时**（批次15 修的 v-else 泄漏是反面教材）；同一面板同时只允许一个主视图分支渲染。

## 2. 元素布局规范

**P7 按钮位置**：主操作 = 编辑面头部动作位或底部动作条（左主右次：`.control-primary` 左、`.control-quiet` 次）；破坏性操作 = `--control-danger` 语义色＋二次确认（弹窗内确认态，不另开弹窗）；**常驻按钮每 pane ≤1 主操作**，其余收进 Ctrl+S/右键/历史。

**P8 提示位置**：错误 = `.pane-error`（面板顶部）；警告 = 列表尾部 `.pane-warn`；帮助性说明 = `.pane-hint`（空态行）；瞬时反馈 = chip。**不跨面板复用横幅**（banner 只在外壳层用于装载失败）。

**P9 排版节奏**：面板纵向节奏 = `--nx-section-gap`（18px）——头部/内容/动作三段；正文区 `.editor-area` 占满剩余高度；列表行用 `.workspace-nav-item` 词汇（行高 42 系）。

## 3. 组合排版规范（并排）

**P10 不得假设独占中栏**：载体布局必须在「全宽」与「半宽（≥420px）」下都可用——编辑区 `flex:1`、列表列宽用 min/max 而非固定 px、头部动作可换行（flex-wrap）。
**P11 分屏合同（预告，M6 前不实现）**：未来并排 = 中栏分屏容器（左右两 pane，拖拽分界，`pane.split: 'main'|'side'` 声明）；协议 v1 先立「载体不假设全宽、不假设独占」，分屏实现时零改造兼容。
**P12 相邻不打架**：两个载体并排时，各自的面板词汇相同（同一套 header/按钮/行高），视觉上只有内容不同——这就是「不出现按钮飘在天上」的机制：**位置由协议定，内容由插件给**。

## 4. 内容格式适配（TXT / MD / HTML …）

**P13 renderer 注册制**：内容格式 = 宿主注册的 renderer，载体声明 `contentFormat`（v1：`text` = `.editor-area` textarea；`read` = 只读 pre；`richtext`（ProseMirror）与 `html`（只读沙箱 iframe，CSP 允许）记账未做）。载体**不自带编辑器实现**——换格式 = 换 renderer，全框架一致。

## 5. 设置与命令的注册制（配合 U13）

**P14 设置节注册**：manifest 加可选 `settings: [{ id, title, group }]`——统一二级页「载体」组自动收录（组件经 impl.settings 提供或先用占位）。本批先落注册机制与「载体」组，各载体具体设置节内容后续批。
**P15 命令面（预告）**：载体的用户可见动作未来登记进命令面板（Obsidian Ctrl+P 同款）——v1 不实现，先立「载体不直接加按钮，动作登记制」的方向。

## 6. 机器门禁（协议不是口号）

1. `visual-contract` 新增：AppNext 与 CarrierPaneHost 源码**不得出现「保存为第」**（P3 文案门禁）；四个视图的头部必须含 `.pane-sub`（P2 抽查 CarrierPaneHost）。
2. `shell-contract`：MENU_TEMPLATE 顶层 label 断言改为 `['项目', '编辑', '设置', '帮助']`（菜单精简的钉子）。
3. `SettingsModal` 分组断言：目录含「应用」「项目」分组标题（P/B 工单落地钉子）。

## 7. 本协议不覆盖的（记账）

- pane 内部的领域交互规范（如漫画画布的缩放手势、跑团的骰子 UI）——各载体自己的事，协议只管框架契合面。
- 多窗口（同开两个项目）未设计。
- 深浅主题之外的高对比模式未设计。

# v1.1 修订：载体即独立栏（作者 2026-10-28 模型修正）

> 作者原话：①「点击小说，看到的就是非常纯粹的小说页面，里面只有正文，按卷、章一层一层往下分；剧本就是按第一幕、第二幕往下推」；②「左侧竖着的功能栏，每一个模块都是独有的栏——小说是一栏，大纲是一栏，世界书、设定、资料也都是独立的栏」；③「大纲或小工具卡片，未来可以设计成左侧的功能小栏——例如大纲变成微型悬浮窗，悬浮在小说正文的某个位置，能随时收起或展开」。

## v1.1-A 载体 = 独立栏（修正 v1 的"载体可拥多 dataDirs 混合板"）

- **一个载体 = 竖条一格 = 一棵纯粹的本域内容树**。索引窗只渲染本载体 dataDir 的内容层级——小说板不出现提案区、大纲区、构思区（批次11 把它们嵌进小说板是**模型错误**，本批纠正）。
- **载体拆分**：novel 拆出 **outline**（大纲，dataDirs 大纲，outline_read/save＋层级树）与 **notes**（构思，dataDirs 构思，notes_list/save）两个独立载体；novel 瘦身为只管 正文。setting（世界书＋约束）保持合并——两棵树同属设定域；若作者要约束独立栏，同法再拆（预留给作者）。
- **内容层级 = 文件目录即层级**：正文/`<卷名>/<章文件>.md` ⇒ 索引窗「卷」节点→「章」叶子；剧本 幕→场同构。fileService.list 需支持子目录分段列举（现只列一层——本批扩展）。
- **竖条顺序**：作者可配（v1 按注册顺序：小说/大纲/构思/设定/资料）。

## v1.1-B 提案与 AI 产物的归属

- 提案（chapter_write 产物）目标是正文，但**不是正文**——不进小说索引窗。迁至统一二级页「文档」组新节「提案审阅」（列提案→点开→中栏对照＋采纳，与文档历史同形态）。正文树的纯粹性优先。
- Agent 对话流中的提案回执卡（右栏）后续批做——先把列表面立住。

## v1.1-C 悬浮小工具窗（新 pane 形态，作者点名）

- **P16 悬浮窗形态**：载体可声明 `slot: 'overlay'` 的 pane——宿主提供**浮动卡片容器**（悬浮于核心区之上、可拖动定位、可收起成侧缘小标签、可展开；z-index 高于编辑器低于统一二级页），内容由载体渲染。
- 定位与收起状态记忆进偏好 JSON（应用级，键 `overlay.<paneId>`）；**同一时刻每载体至多一个悬浮窗实例**（多开后续批）。
- 首个实现：**大纲悬浮窗**——大纲载体声明 overlay pane，迷你视图（当前章大纲节点＋折叠全大纲），悬浮于正文右上，随时收起。
- 机器门禁：overlay 容器为宿主组件（`FloatingWidget.vue`），载体 SFC 不得自带拖拽/定位逻辑（grep 断言）。

## v1.1-D 机器门禁

1. 索引窗纯粹性：novel 板索引窗源码不得含 提案/大纲/构思 字样的区块（grep 断言，随拆分落地生效）。
2. 竖条载体数断言：registry 注册 N 载体 ⇒ 竖条 N 格＋主题钮（shell-ui 断言）。
3. 悬浮窗：载体 SFC 不含拖拽逻辑（P16）。
