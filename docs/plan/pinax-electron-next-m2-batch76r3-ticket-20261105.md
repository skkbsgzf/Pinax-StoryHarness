# 批次76-R3 工单：页签行归组（VS Code 编辑器组模型）（2026-11-05）

> 调度方：Zcode。执行方：Qoder CLI（Qwen3.8-Flash）。
> 触发：作者看对半双嵌实拍的裁定——「右半孤零零地展示，应该显示它分屏的那个窗口的名字。IDE 里面可以把两个代码并排，它是什么个逻辑？你用它那个逻辑啊」。
> **本批是对 76-R2「合一条」的修正：合错了方向——不是全屏合一条，而是每组一条。**

## 作者裁定（原文要点）

1. 右侧半屏若有窗口与左边分屏，右侧必须**显示那个窗口的名字**，不能孤零零空白。
2. IDE（VS Code）的模型：打开很多编辑器，可以把任意两个并排——**每个分屏组有自己的页签行**，列的是该组开着的编辑器，活动签即标题。

## 目标模型（VS Code 编辑器组语义）

- **每组一条页签行**，渲染在该组内容上方：列出**本组**的页（main 组列 main 的，side 组列 side 的），活动签高亮即标题，× 在签上，拖签＝换组/换形态的起点（VS Code 拖签分屏的对应物）。
- **组永远自报家门**：side 组只有一页时，那一条签也照常渲染（ComfyUI 并排时，右半头顶写着「ComfyUI」）。任何可见内容区，头上必有签——「孤零零空白半屏」为违规态。
- **全局不再有唯一的总页签条**。批次61 那条跨组总条与 76-R2 的「待开页签」合并进各组：待开的承载位以虚线签挂在本组条尾；无处归属的（floating/tab 态页）归**主组条尾**收留（它们仍是可点开的落点，落点语义不变）。
- 空组（无页可列）整组连同条一起不渲染——不会出现「有条无内容」。
- 收进悬浮球的页、浮窗：浮窗自带窗头（76-R2 已定）；悬浮球态的签收进主组条尾或右键，以实现最小者为准，工单不自设新形态。

## 任务（四条）

1. **PaneTabStrip 拆组**：从「全局一条列全部页」改为「按组渲染，一条只列本组」——`group` 作为条的属性；AppNext 里 main/side 各挂一条（side 组不存在则不挂）。76-R2 的待开页签与拖拽起点逻辑**原样保留**，只是归属从全局条改为组条。
2. **组签行几何**：每组条固定在组内容顶部（组内 flex 首 行，不浮不叠）；两组条各自独立高亮各自的活动签（VS Code：焦点在哪组，哪组签亮，**互不抢**）。侧组条加与 76-R2 同款的左缘分隔视觉。
3. **违规态消除**：任何 state==='page' 的窗口渲染时，其所在组必须有可见条且该页的签在列——写进守卫（有窗必有签）。同时清掉旧全局条的残留样式与测试。
4. **回归**：批次61/66/76-R2/77 的页签测试全部按组模型改写，行为语义不删（点＝揭示、×＝关、拖＝换形态、右键菜单、待开页签开面、悬浮球回收）。分组后「揭示另一组页」=把焦点给那组（VS Code 点击另一组签就是切焦点，不搬家）。
